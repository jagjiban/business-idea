# Business Ideas Repo

This repo stores and develops business ideas as markdown documents. It is not an app codebase.

## Owner context
- Software engineer: JavaScript, React, Node.js, GraphQL, HTML/CSS, PHP, and some AWS.
- Builds vendor marketplace apps (third-party app marketplaces) at a company whose main product is timesheet software.
- Flag any idea that overlaps with the employer's product or market (IP and non-compete risk).

## Structure
- `README.md`: index of all ideas, one row each, with status. Keep it in sync whenever an idea is added or changes status.
- `_template.md`: skeleton for every idea. Copy it for new ideas; don't change its sections without asking.
- `ideas/NNN-short-slug.md`: one file per idea. Number sequentially (001, 002, …) and use a lowercase kebab-case slug.

## Statuses
💡 Raw → 🔍 Researching → ✅ Validated → 🚧 Building → ❌ Dropped

When an idea is dropped, keep the file and write down why. The reasons are worth having later.

## Working conventions
- A half-formed idea is fine. Fill what you can from the template and list the gaps under "Open questions"; don't invent facts.
- Label every claim from research with its source (a link) and the date it was checked. Mark estimates clearly as estimates.
- Be honest about weaknesses. The goal is to find the best idea, not to cheerlead each one.
- Prototypes or code for an idea go in a separate repo. Link it from the idea file.
- Update the "Last updated" date in an idea file whenever it changes.
